#+TITLE: visual-regexp-rx
#+AUTHOR: Kazure Zheng

visual-regexp-rx is an extension to [[https://github.com/benma/visual-regexp.el][visual-regexp]]
which enables the use of =rx= notation (structured, Lisp-style regular expressions)
instead of Emacs-style regexp strings — the way
[[https://github.com/benma/visual-regexp-steroids.el][visual-regexp-steroids]] enables
PCRE (Python regular expressions).

* Installation

visual-regexp-rx depends on [[https://github.com/benma/visual-regexp.el][visual-regexp]] ≥ 1.1:

#+begin_src elisp
;; if the files are not already in the load path
(add-to-list 'load-path "folder-to/visual-regexp/")
(add-to-list 'load-path "folder-to/visual-regexp-rx/")
(require 'visual-regexp)
(require 'visual-regexp-rx)
#+end_src

or with use-package:

#+begin_src elisp
(use-package visual-regexp
  :load-path "folder-to/visual-regexp/")

(use-package visual-regexp-rx
  :load-path "folder-to/visual-regexp-rx/")
#+end_src

Requires Emacs ≥ 28.1.

* Usage

Select the rx engine once, then use visual-regexp's own commands:

#+begin_src elisp
(setq vr/engine 'rx)
#+end_src

- =M-x vr/query-replace=: confirm each match with y/n (query replace)
- =M-x vr/replace=: replace all matches at once

In the minibuffer, type an rx form instead of a regexp string, e.g.:

#+begin_src text
(seq "TODO" (+ blank) (group (+ nonl)))
#+end_src

Matches =TODO= followed by one or more spaces or tabs and captures the rest
of the line in group 1, e.g. it matches =TODO fix the login bug=.

Beyond plain visual-regexp, this package adds:

- The regexp minibuffer is prefilled with =(seq "")=, point left between
  the quotes, ready for typing.
- Empty =()= placeholders are treated as =(seq)= while the form is under
  construction, so highlighting does not disappear.
- The pristine prefill compiles to a never-matching regexp, so the first
  render does not flood the buffer with zero-width matches.
- The prefill and the empty-match suppression are configurable:
  - =visual-regexp-rx-prefill-form= (string, default ="(seq "")"=): the
    form prefilled in the regexp minibuffer.  Set it to =""= to disable
    the prefill and start with an empty minibuffer, or to any other
    one-line rx form to prefill something else.  Point ends up inside
    the first =""= of the form, or after it when there is none.
  - =visual-regexp-rx-suppress-empty-highlight= (boolean, default =t=):
    whether the untouched prefill is kept from highlighting anything.
    Set it to =nil= to let the prefill render as visual-regexp would,
    i.e. an empty-match marker at every buffer position.
  - =visual-regexp-rx-completion= (boolean, default =t=): whether the
    minibuffer offers completion at point while you type an rx form.
    The candidates are the built-in rx names — filtered by their
    position in the form, so =(syntax ...)= only offers syntax codes,
    =(any ...)= only character classes, and so on — plus the names you
    defined with =rx-define=.  Each candidate is annotated with its
    kind, and the popup info (Corfu's =corfu-popupinfo= or =M-h=) shows
    what it means.  Any completion UI built on
    =completion-at-point-functions= picks it up, and =C-M-i= completes
    on demand.

For example:

#+begin_src elisp
;; no prefill: start with an empty minibuffer, like plain visual-regexp
(setq visual-regexp-rx-prefill-form "")

;; do not suppress the empty-match markers of the untouched prefill
(setq visual-regexp-rx-suppress-empty-highlight nil)

;; no completion at point in the rx minibuffer
(setq visual-regexp-rx-completion nil)

;; prefill something you want to extend while typing
(setq visual-regexp-rx-prefill-form "(seq \"TODO\" \"\")")
#+end_src

Everything else — the live preview, the query loop and all minibuffer
shortcuts — is plain visual-regexp.

Set =vr/engine= back to =emacs= for plain visual-regexp behavior.

To customize, use =M-x customize-group [RET] visual-regexp=.  The =rx= choice
is added to =vr/engine=; when visual-regexp-steroids is installed, its
existing option is extended instead.

* How it works

One around advice, one prefill hook and one completion function, no new
commands:

- =vr--get-regexp-string= is advised =:around=: when =vr/engine= is =rx=,
  the minibuffer input is =read= as a Lisp structure and compiled with
  =rx-to-string=; empty =()= placeholders are recursively replaced with
  =(seq)= first.
- Calls with =for-display= non-nil keep the raw input (it is only shown,
  not used).
- A =minibuffer-setup-hook= prefills =visual-regexp-rx-prefill-form=
  on the regexp minibuffer in rx mode (nothing is inserted when it is
  empty).  The pristine flag is cleared on the first edit, and while it
  is set the form is compared against =visual-regexp-rx-prefill-form=
  and, if =visual-regexp-rx-suppress-empty-highlight= is non-nil,
  replaced by a never-matching regexp.
- Conversion errors are re-signalled as =invalid-regexp= and shown by
  visual-regexp's own error display.
- In rx mode the same =minibuffer-setup-hook= adds a buffer-local
  =completion-at-point-functions= entry (and removes it again on the
  other minibuffers, e.g. the replacement prompt).  The candidates come
  from rx's own tables (=rx--builtin-forms=, =rx--builtin-symbols=,
  =rx--char-classes=, =rx--syntax-codes=, =rx--categories=) and from the
  =rx-definition= properties; =syntax-ppss= decides whether point is at
  the head of a form, in a specific argument position, or inside a
  string.

* Limitations

- Relies on visual-regexp's private API =vr--get-regexp-string= (verified
  with version 1.1; check the visual-regexp source for future versions).
- Completion reads rx's private name tables (=rx--builtin-forms=,
  =rx--builtin-symbols=, =rx--char-classes=, =rx--syntax-codes=,
  =rx--categories=) and the =rx-definition= symbol property; these are
  stable across the Emacs versions this package supports (verified with
  28.1, 29.4, 30.1 and 32), but they are not part of rx's public API.
- =vr/engine= is shared with visual-regexp-steroids; if steroids is loaded
  after this package it redefines the variable and overwrites the choice
  list (=rx= remains usable via =setq=).
- Rx forms are typed on one line; build complex multi-line forms in a
  scratch buffer and paste them in.
- Forms are =read= and compiled with =rx-to-string=; don't write
  side-effecting code in them.
